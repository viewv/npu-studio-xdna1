# RVM NPU：拆"每层开销"、压到 9.2 ms

接 quant spike。上一轮真实编码器 11.4 ms，`reps` 拆分说纯计算 2.8 ms、其余 8.5 ms 是"每层固定开销 0.12 ms × 70 层"。
这一轮先拆开这 8.5 ms 到底是什么，再改。

## 结论

1. **真实编码器 11.4 → 9.6 ms（中位）/ 9.2 ms（最快）**，和整数模拟仍逐字节一致，`npu.check` 22/22。
   随机权重同一负载 A/B：11.15 → 9.15 ms（−18%）。`reps` 拆分：纯计算 2.7 ms + 截距 6.6 ms（原 8.6）。
2. 三处改动，都在 `chain_c16.py` 的 Plan / runtime sequence，**内核没动**：
   | 改动 | 最快（ms） |
   |---|---|
   | 原来 | 11.15 |
   | 权重元素 18.9 KB → 9.8 KB（`W_SMALL`）+ 权重 fifo 深度 2（算这一步时预取下一步） | 9.93–10.05 |
   | task group 流水：每组 2 个 fill，发完下一组再等上一组（`TG_INFLIGHT` = 2） | 9.34–9.41 |
   | 下一层第一组的权重在层间屏障之前发（`W_PREFETCH`） | 9.13–9.17 |
3. 还是比 onnxruntime CPU 单线程（8.4 ms）慢一点。剩下的非计算开销主要是层间屏障（每层 ~30 µs）和每步固定代价；
   下一步要靠倒残差块融合（少层、少步），调 DMA 参数已经到头了。

## 怎么拆的（有两次猜错）

- **猜 1：权重流量**（443 步 × 4 core × 18.9 KB = 33.6 MB，真实权重只有 4.3 MB）。
  对照：同一条单步层的链把 e_w 从 6.6 KB 强行补到 18.9 KB，每层代价不变（0.034 ms）。
  —— 单步层的权重在层间屏障时就搬完了，看不出来；多步层上才有影响（见下）。
- **逐层边际**（70 个前缀）+ 按层回归（输入字节、权重字节、输出字节、计算量）：回归说输入字节占 5 ms（≈ 3.8 GB/s 每 core）。
- **猜 2：输入带宽 / 重读**。照回归改了 ict 的切法（行切细、每份多几个通道组，输入少读一半）：**整体慢 0.6 ms**。
  微基准：256→256 1×1 在 4×20 / 8×20 / 12×20 上，8×20 的输入只有 12×20 的 1/3、步数相同，反而更慢；`reps` 2 倍计算时间不变。
  → 回归被共线性骗了（输入字节和步数、task group 数一起涨）。代价是**按步、按 task group 算的**，不是按字节。
- **BD 个数**：同样字节的 fill 拆成 3 个 BD，没区别。
- **task group 数**：`FILLS_PER_TG` 1 / 2 / 4 → 16 / 8 / 4 组，0.46 / 0.32 / 0.27 ms → 每组 ~16 µs 的屏障（组之间 DMA 队列是空的）。
- **每步的权重**：4×20 的 ict 层，e_w 4.9 → 18.9 KB 每步多 ~2.2 µs；深度 2 每步省 ~1.4 µs。
  深度 1 时下一步的权重只能在 core 释放这一步之后才开始搬，盖不住。（tiling spike 那时测"深度 2 没收益"，当时瓶颈在多读的输入。）

## 细节

- 小元素 + 深度 2：`Plan` 先用 `W_SMALL` 选切分，有层放不进（大 3×3，如 enc / deep 链里的 3×3 128 通道）就退回 `W_BIG` + 深度 1；
  深度 × e_w ≤ `W_BUDGET`（20 KB），内存和原来差不多（每 core 约 62.9 KB）。真实编码器 443 → 468 步、e_w 9728 B。
  1×1 层一个输出组的权重放不进小元素时改走 IC 分块（原来直接报错），ict 的每步通道组数也受 W_MAX 限制。
  扫过 6 KB × 2/3、4.6 KB × 3/4：都不比 9.8 KB × 2 快（步数涨得更多）。
- task group 流水：IRON 的 runtime sequence 按调用顺序发任务，`finish_task_group(tg)` 只是在那里插 await / free，
  所以可以先开下一组再结束上一组。挂死的规则是**每个 shim 通道在途任务合计 ≤ 4**（tiling spike 里"一组 7 个 fill 挂死"）：
  每组 2 个 fill × 2 组在途；权重通道再加一个预取 = 3。试过 1 个 fill × 2/3/4 组在途，都比 2 × 2 慢。
- shim 分配（看 `input_with_addresses.mlir`）：shim c 的 MM2S0 = core c 输入、MM2S1 = core c 权重；
  core 0/1 的输出在 shim 0 的两个 S2MM，core 2/3 在 shim 1。
