# RVM NPU：接真实权重、选量化方案、真实编码器上 NPU

接 act-res spike。之前所有内核都是"随机权重 + 只移位"的自定义整数算法。这一轮把真实的 RVM（MobileNetV3）编码器权重接上：
先在 numpy 里选量化方案，再改内核支持它，最后让 NPU 和 numpy 整数模拟逐字节一致。

## 结论

1. **真实编码器（70 层、443 步）在 NPU 上和整数模拟逐字节一致**（8 张图，f1..f4 四个特征张量全部 0 差）。已加进 `npu.check`（22/22）。
2. **精度**：反量化后对 onnxruntime 浮点的余弦 f1 0.998 / f2 0.966 / f3 0.943 / f4 0.879。
   onnxruntime 自带的 int8 静态量化（逐通道权重）在同样的图上最好只有 f4 0.84，所以这套方案已经不差；
   误差基本全来自 8 位激活（16 位诊断时 f4 0.998）。**最终 alpha 还没看**（见"还没做"）。
3. **速度是坏消息**：NPU 11.4 ms，onnxruntime CPU 单线程 8.4 ms、4 线程 3.1 ms。
   拆开看纯计算只有 2.8 ms，**每层固定开销 0.118 ms × 70 层 = 8.5 ms**。下一阶段的主题应该是压每层开销，而不是加算子。

## 量化方案（细节和误差表在 skill 的 `references/quant.md`）

- 激活：对称 int8、**逐通道比例**、每通道 MSE 最优截断。逐通道比例在 NPU 上不花额外代价：
  - 生产者本来就有逐通道的 M，直接量化到各通道自己的比例；
  - 消费者是卷积，把输入通道的比例折进权重（`W[o,c]·s_x[c]`）再按输出通道量化，是精确的。
- 权重：对称 int8，逐输出通道。
- 重新量化：`y = sat8((sat16((acc + bias + 2^(s1−1)) >> s1) · M[c] + 2^(s2−1)) >> s2)`，M 是逐通道 int16，s1 由校准集定（2 倍余量）。
  和浮点乘相比几乎没有损失（f4 0.873 vs 0.881）。
- hardswish：先量化到 1/q_c（"3"和"6"是精确的整数 3q、6q），y·clamp(y+3q, 0, 6q) 再重新量化一次。
- HardSigmoid：FC2 量化到 6/256，输出 y + 128 正好是 clamp(x/6 + 0.5)。残差、SE、池化沿用前几轮的做法。

几种对照（f4 余弦）：逐张量 + 最大值 0.653 → 逐张量 + p99.9 0.837 → **逐通道 + MSE 0.881**；ReLU 改 uint8 只多一点点，不改内核。

## 内核改动

- 累加器初值 = bias；输出 = `to_vector<int16>(s1)` × M → `to_vector<int8>(s2)` → `max(·, lo)`。
  逐通道参数（bias、M、hardswish 的 q3/q6/M2）放在每步权重后面的**重新量化表**里（每个输出通道组 576 B，主机侧已排成向量布局）。
- 有了 bias，宽度外的像素不再自然是 0：4 像素组里部分有效时显式清零（只有 1×1 图的 FC 会遇到）。
- act 0 也改成 int8 的 ReLU（0..127），去掉了"输出 uint8、下一层当 int8 读"的实验约定。
- 随机测试的默认参数（bias 0、M 1、s1 = shift、s2 0）等价于原来的"只移位"，所以老的链全部逐字节不变；
  `--rq` 用随机 bias 和 M 测新路径（res144、mnv3r 都过）。
- **程序内存**：第一版超到 17.8 KB（编译到最后报 `Overflow of program memory`）。
  去掉 uint8 分支、下限改成无分支的 max、罕见分支挪出去、dw 的 stride 改运行时（5 个模板实例 → 3 个），回到 15.25 / 16 KB。
  新工具 `python -m npu.ksize` 按函数列大小。
- 代价：新的输出路径整体慢约 9%（每个输出多一次 int16 乘法，权重元素也大了 576 B / 组）。

## 踩的坑（按发现顺序）

1. **死通道**：有些通道权重全是 0，按通道最大值算出的比例约等于 0，bias / 比例就溢出了。
   第一版模拟连 16 位都只有 f4 0.25，加了 16 位诊断才发现是 bug 而不是量化噪声。给比例设下限后，16 位到了 0.998。
2. 模拟里 HardSigmoid 的输入没夹到 int8（只在 16 位诊断时暴露）。
3. **SE 折了两次**：导出给 NPU 的投影层权重是模拟里已经乘过 SE 的，内核又乘了一次。
   定位方法：逐层读回 NPU 的张量和模拟比，第一个错的层再用 numpy 拿几种假设（不乘 / 乘一次 / 乘两次）去对 NPU 的输出。
4. **死通道的 hardswish q** 算出 12614，6q 超过 int16，NPU 上那个通道整片错。这个通道后面权重为 0，所以 f4 没受影响，
   只有逐层比对才看得到。q 封顶 4096。
5. HardSigmoid 的输出是 uint8，读回来按 int8 和模拟比会差 256。是比对方式的问题，不是 bug。

## 还没做 / 下一步

- **每层开销**（75% 的时间）：把倒残差块（升维 → dw → 投影）融合成一层、中间张量留在 core 里；少分 task group；跨层预取权重。
- **用真实画面看最终 alpha**：校准和评估用的是系统壁纸（没有人像）。要用摄像头画面校准，把 NPU 的编码器特征接到浮点解码器
  （onnxruntime 的子图），看 alpha 的误差。如果 alpha 不够好，考虑部分层 16 位激活或量化感知训练。
