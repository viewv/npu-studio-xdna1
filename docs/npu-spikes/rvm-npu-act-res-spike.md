# RVM NPU：省程序内存、hardswish、残差加

接 SE spike。目标是把 MobileNetV3 编码器剩下的两种算子做完：hardswish 和残差加（Add）。上一轮程序内存已经到 14.0 / 16 KB，
所以先省内存再加东西。

## 结论

- RVM 编码器用到的算子都能跑了。`mnv3r`：真实激活（第一层和后半段 hardswish、投影层线性、其余 ReLU），
  加 4 个 SE、4 个残差加，39 层逐字节一致。`npu.check` 19/19。
- 同一负载（≈ 3）下的最快值：mnv3 5.06–5.12 → mnv3se 5.73–5.82 → mnv3a（真实激活）5.91–6.06 → mnv3r 6.18–6.29 ms。
- 程序内存 14.0 → 13.2（省）→ 14.4 KB（加激活、有符号池化）。剩 1.6 KB。

## 1. 省程序内存：池化和装缩放向量不再单独占一段循环

上一轮给"装 SE 缩放向量"和"池化"各加了一段 core 循环，core 程序从 3.2 涨到 4.4 KB。改法：

- 装缩放向量 = 层前面多一个槽，走现有的累加段（rows = 元素数，nch = 1），权重头 `h[42]` 告诉内核这是装载。
- 池化 = 两个槽：累加段收每组前 ne−1 个元素（rows = 组数·(ne−1)，部分和放 `acc[16·组]`），
  收尾段收每组最后一个元素并出块（rows = 组数）。fill 也拆成两个 BD，按这个顺序发。
- 内核不再用 j < 0 区分特殊调用，改看权重头的标志。

core 程序回到 3.2 KB，总共省了 0.8 KB。代价是每个 SE 多 2 个槽（每槽约 5 µs）。

## 2. 输出激活

`Layer.act`：0 ReLU（uint8 饱和）、1 HardSigmoid、2 线性（int8 饱和）、3 hardswish（int8）。

- 卷积内核（3×3 s1/s2、1×1、5 种 dw）只分两种存法：uint8 饱和或 int8 饱和（`Desc.sgn`）。每个存储点只多一个分支。
- HardSigmoid / hardswish 在入口函数最后对整个 640 B 输出块做（`post_act`），**整个内核只有一个调用点**。
  hardswish 的整数定义：`y = sat8(acc >> s)`，`out = sat8((y · clamp(y + 3q, 0, 6q) + 2^(s2−1)) >> s2)`，
  q = y 里 1.0 对应的整数（实验用 20），输出比例 = 2^s2 / (6q²)。接真实模型时 q、s2 从量化参数来。
- 池化的输入可能是有符号的（hardswish 的 dw 后面接 SE）：输入异或 0x80 当 uint8 累加，收尾时减掉 128 × 像素数。
  零边在异或后是 128、减掉以后还是 0，所以不用区分边和内部。
- **软件流水**：`post_act` 第一版每层多 0.015–0.065 ms，反汇编显示每 32 B 一条 22 拍的依赖链，编译器没有做软件流水。
  改成每轮 4 个独立向量后是 0–0.03 ms。定长小数组完全展开后全在寄存器里（反汇编确认没有栈访问）。

## 3. 残差加 = 通道拼接 + 单位权重

`Layer.cat`：层读 `[张量 src ‖ 张量 cat]`。Plan 把 B（块的输入）放进 A（dw 输出）的存储，排在 A 的通道组后面：
`Tensor.ctot` 是合计通道数，`Tensor.g0` 是 B 的起始组。写 B 的层（上一个块的投影层）直接写到位，不用搬。
投影层把两者当一个更宽的 1×1 输入，残差那部分的权重是 `64·I`。**内核一行没改**，这也是解码器 Concat 要用的布局基础。

SE 和残差同时出现时（Conv_47、Conv_144），SE 只乘前面 dw 那部分的组（`h[48]`）。

代价（逐层对照，最快值）：

| 层 | 无残差 → 有残差 | 为什么 |
|---|---|---|
| Conv_24（80 + 32 @45×80） | +0.017 ms | 拼完一行还放得下，多算的是 32 个输入通道 |
| Conv_47se（128 + 48 @23×40） | +0.128 | 11 组放不进一行（最多 10 组）→ 掉进 IC 分块；每 core 6 行 acc 放不下 → 新加的"IC 切行" |
| Conv_74m（208 + 80 @12×20） | +0.191 | 18 组 > 15 → IC 分块 |
| Conv_144se（960 + 160 @12×20） | +0.350 | IC 步数 4 → 5，输入按 10 份 OC 重读 |

贵的那几个是 IC 分块"按 OC 份数重读输入"的老债被放大。换成在内核里直接加残差也省不掉这部分 DMA
（输入元素固定 7680 B，按元素算钱），所以记成性能债，没有在这一轮处理。

### IC 切行

Conv_47se 带残差后走 IC 分块，但 23×40 每个 core 6 行，acc 只放得下 3 个块的部分和。
现在每个 core 的行再切成几段（`Tiling.n_rb`，每段 ≤ `rcap` 行），份号 o 对应（OC 块 o // n_rb，行段 o % n_rb），
每份只读写自己那段行。第一次就逐字节对上。

## 坑和小结

- 激活在 0 处不为 0 的规则（上一轮）在这一轮仍然只有 HardSigmoid 需要处理：hardswish(0) = 0，线性也是。
- 单独跑 SE 投影层或残差投影层会因为 src / cat 越界报错。测单层要带上前面的层，或者用不带分支的版本（`Conv_131m`）。
- `deep` 链这次测出来是 2.60–2.64 ms（之前 2.43–2.66），主要是负载；没发现回退。

## 下一步

- 解码器：Concat（拼接视图有了，要支持"两个张量都在算之前就决定放在哪"的一般情形）、Resize（2× 双线性上采样）、ConvGRU（Sigmoid / Tanh、逐元素乘加）。
- IC 分块的输入重读（性能债第 1 条）现在影响更大：残差把 3 个投影层推进了 IC 分块。
