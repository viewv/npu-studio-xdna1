# RVM 整网上 NPU：depthwise 卷积（dw spike）

日期 2026-11-12，分支 `phase2-npu`，未提交。接 `rvm-npu-tiling-spike.md`。
代码：`npu/chain_c16.py`（dw 规划 / TAP / 打包 / 参考，张量上下边 1→4 行）+ `npu/kernels/conv_c16.cc`（dwconv 模板）。
`npu.check` 加了 `chain_c16 mnv3 27 层`，完整 12/12 通过。

## 结论（一句话）

**RVM 里所有 depthwise 形态都能跑了，逐字节一致**：3×3 s1/s2、5×5 s1/s2、5×5 dilation 2，通道 16–960，分辨率 90×160 → 12×20。
用 RVM 编码器（MobileNetV3）主干的真实形状串成 27 层（9 个 depthwise + 1×1 升降维 + OC/IC 分块），一次 NPU 调用 **4.9–5.2 ms**（最快）。
depthwise 计算只占 2.3%，但在链里占约 1.8 ms，最贵的是 12×20 的两个 5×5 dilation 2（+0.36、+0.46 ms）。

## 做法

- **窗口**：5×5 dilation 2 纵向跨 9 行，fifo 滑窗放不下。改成 DMA 给每个输出行把要的 k 行（按 s、d 隔行/重复）放进**一个**输入元素：
  元素 = `[k 行][m 个通道组][PLANE]`，TAP `[输出行, ky, 组, PLANE]`、步长 `[s·行, d·行, 组, 1]`（每 64 个输出行一个 BD）。
  core 每行 acquire 1 / release 1 → **直接复用 IC 分块的"收尾段"循环，core 代码没加一行**。
- **通道**：depthwise 各通道独立，每步 m 个通道组（m 取 k·m·PLANE = 7680 能放下的最大值），输入不重读；每步一个 drain。
- **上下边**：所有张量的上下零边从 1 行扩成 BR=4 行（5×5 d2 的 pad = 4）。原有链全部照旧逐字节一致。
- **内核**：逐元素 `aie::mac`（AIE2 的 8×8 位逐元素乘是 32 路一条，64 路两条，峰值是 mmul 的 1/8，dw 计算量小，够用）。
  权重主机侧复制成 `[组][ky][kx][4 像素][16 通道]`，对上 4 像素×16 通道的 64 B 向量；水平偏移 o = kx·d − pad ∈ [−4, 4] 像素
  用 shuffle_up/down_fill 从相邻向量拼（±4 直接用邻居向量）。stride 2 先按 stride 1 算两倍的位置、再 `filter_even(·,16)` 取偶数像素。
- **模板化**：`dwconv<K, D, S>` 编译期展开 kx、移位量是常量，按 RVM 用到的 5 种组合分派。运行时参数版慢 2–3 倍（mnv3 8.95 → 5.17 ms）。

## 踩到的坑：栈溢出

第一版 stride 2 路径在栈上放了 `ACC64 a[4]`（4 × 256 B）+ `V64 v[6]`，函数被内联进入口 → **所有调用**（包括普通卷积）都分这么大的栈帧，
超出 core 的栈 → 普通链结果错（差 255）、单层直接挂死。改成每次只算 2 组、不用数组，dwconv 标 `noinline`。
**以后内核里别放向量/累加器数组。**

## 下一步

1. 12×20 的 depthwise 还贵：每 core 3 行 × 20 步，每步 7.7 KB 输入元素里大半是垃圾（plane 512 B 但 k·m 组织）。可以像 OC 并行那样给低分辨率 dw
   做"通道并行"（每 core 不同通道组、全部 12 行），步数 /4、每步 4 倍计算。
2. 继续扩算子（覆盖面）：SE（全局平均池化 + 两个小 FC + HardSigmoid + 乘回去）、hardswish / 残差加（融进卷积尾部）、
   解码器的 Concat / Resize / ConvGRU。
3. 程序内存：`.text` 10.5 KB，新算子尽量复用现有分支；必要时把一部分算子放到单独的 core 程序（另一组 Worker）。
