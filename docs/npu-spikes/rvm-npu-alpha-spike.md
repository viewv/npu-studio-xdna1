# RVM NPU：int8 编码器对最终 alpha 的影响（摄像头实录）

接 overhead spike。之前编码器的精度只在特征层面看过（对浮点余弦 f4 0.88），校准 / 评估图是系统壁纸、没有人像。
这一轮用摄像头录一段真实画面，看最终 alpha。

## 做法

- `npu/rvm/alpha_check.py`：两路同时逐帧跑、各自带循环状态 r1..r4：
  - 参考：onnxruntime 浮点 RVM 整网；
  - 量化：NPU 编码器（真实权重，int8）→ 读回 f1..f4 反量化 → onnxruntime 浮点**解码器子图**（`onnx.utils.Extractor`，输入 src + f1..f4 + r*i）。
- 素材：/dev/video0 1280×720 MJPG 录 10 s（302 帧），按 studio 的做法 INTER_AREA 缩到 320×180。室内偏暗，转头、前后移动。
  帧只留在本地 scratchpad，不进仓库。
- 公平比较：前 151 帧里抽 16 帧校准，后 151 帧评估。

## 结果（后 151 帧）

| 校准 | MAE 全图 | 边缘带 | \|差\| > 0.1 的像素 | 前景 IoU（最差） | 多出来的帧间闪烁 |
|---|---|---|---|---|---|
| 系统壁纸 16 张 | 0.39/255 | 5.3/255 | 0.40% | 0.994（0.991） | 0.40/255 |
| 真实画面 16 帧 | **0.18/255** | **2.4/255** | **0.04%** | **0.997（0.995）** | **0.21/255** |

（整段 302 帧、校准帧包含在内时：壁纸 0.49 / 6.0，真实画面 0.25 / 3.1；两种混合介于中间。）

- 误差全在边缘带（参考 alpha 在 0.02..0.98 之间再膨胀 3 像素），非边缘几乎为 0。
- 壁纸校准时，第一帧（循环状态还是 0）深色衣服的肩膀被吃掉一块；真实画面校准后没有。
- 参考本身的帧间变化 1.07/255，量化版多出来的闪烁 0.21/255，肉眼看不出。

## 结论

- **int8 编码器（逐通道激活 + MSE 截断 + m16）对最终 alpha 够用**，不需要 16 位激活或量化感知训练。
- **校准要用真实人像画面**：误差减半。接进 studio 时，校准帧应当在用户机器上从摄像头现录（几秒就够），或者随模型发一组授权过的人像图。
- 这一轮只覆盖一个人、一种光照、一段 10 s；头发细节多、背景杂乱、强逆光的情形还没测。
