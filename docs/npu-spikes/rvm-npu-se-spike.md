# RVM NPU：SE（squeeze-excitation）实验

接 dw spike。目标：把 MobileNetV3 的 SE 块（GlobalAveragePool → 1×1 → ReLU → 1×1 → HardSigmoid → 和特征图逐通道相乘）
放进 `chain_c16` 串联框架，逐字节对上 numpy 整数参考，并看清它在链里的真实代价。

## 结论

- SE 拆成 3 个普通"层"加 1 个带逐通道乘的投影层，全部复用现有的 fifo、DMA 和 task group 结构，没有新 fifo。
  `se39` / `se95` / `se135` 三个单块和 `mnv3se`（主干 + 4 个 SE，39 层）全部逐字节一致，已加进 `npu.check`（16/16）。
- 代价：每个 SE 约 0.14 ms（mnv3 4.99 → mnv3se 5.53–5.59 ms，最快值）。整网 8 个 SE 估计约 1.1 ms。
- 程序内存 10.5 → 14.0 KB（上限 16 KB），这是下一个算子最紧的约束。

## 做法

| 部分 | 怎么做 | 为什么 |
|---|---|---|
| 分支 | `Layer.src`（读哪个更早的张量）、`Layer.sc`（缩放张量）；每个中间张量一个自己的 scratch 槽 | 投影层读的是 4 个张量之前的 dw 输出，按形状乒乓会被覆盖 |
| 全局平均池化 | 新模式 `pool`：core c 拿通道组 c, c+4, …，读这些组的**全部行**；元素 = 一个组的 kr 行；int32 和在 acc 里跨元素累加；均值 `(Σ·M + 2^21) >> 22`（M = round(2^22 / HW)，int32 × int16 向量乘） | 按通道分 core 就不需要跨 core 归约；没有向量除法 |
| FC1 / FC2 | 就是 1×1 图上的 1×1 卷积。只有 1 行，按行只能切出 1 段 → oc 和 ict 都改走 OC 并行；ict 的 1 行 fill 合成一个 BD | 不加新内核分支 |
| HardSigmoid | `Layer.act = 1`：`to_vector<int8>(shift)` 饱和后异或 0x80（= +128）→ uint8，128 表示 0.5 | 一条指令就是 clamp(x/6 + 0.5)；真实的偏移和斜率以后放进 bias / shift |
| 逐通道乘 | 投影层的第一步先从输入 fifo 收 n_pre 个元素（C×1×1 张量连续读，每 768 B 一个组）放进每 core 1 KB 的 `sc` 缓冲区；之后**每步**第一次调用时把 sc 折进这一步的权重：`W' = (W·s + 128) >> 8`（原地，做完清标志） | 见下面的对照 |

### 乘输入还是乘权重

第一版是在每行第一次被用到时原地乘输入：`x' = (x·s + 128) >> 8`。full 模式的投影层只多 0.02–0.04 ms，
但 IC 分块的层每份 OC 都要把输入重读一遍，也就要重新乘一遍：Conv_104 多 0.12 ms，Conv_144 多 0.35 ms。
改成乘这一步的权重后，代价只和权重量有关，和行数、重读次数无关：分别降到 +0.03 ms 和 +0.07 ms。
两种做法在数学上等价，精度损失也对称（都是把一个 8 位量乘以 s/256 再取整），参考实现跟着内核走（`se_weights`）。

## 边际耗时（链里逐层加前缀，最快值）

| 块 | 池化 | FC1 | FC2 | 投影层（含乘） |
|---|---|---|---|---|
| se39（128 通道 @23×40） | +0.019 | +0.044 | +0.017 | +0.050 |
| se95（480 @12×20） | +0.036 | +0.029 | +0.019 | +0.307（IC 分块，大部分是老的输入重读债） |
| se135（960 @12×20） | +0.071 | +0.053 | +0.073 | +0.772（同上） |

SE 本身的 3 层是 0.08–0.2 ms；投影层贵的部分是 12×20 IC 分块的老问题（perf.md 性能债第 1 条），和 SE 无关。

## 踩的坑

1. **缩放向量偏移多加了一次 PAD**：fill 起点已经指向像素 0，内核又加了 `PAD·16`，读到的全是零。症状是投影层完全对不上，
   但"同样的分支输入、不乘"的对照层是对的，所以能定位到乘法。
2. **HardSigmoid(0) = 128 → 补宽列被写脏**（`check` 报 999）：内核按 4 像素一组输出，ReLU 时宽度外的像素自然是 0，
   换成 HardSigmoid 就不是了。按有效像素数把组内多出来的字节清零。
3. **按引用把累加器传给 noinline 函数 → 挂死**：为了省程序内存把 HardSigmoid 的存储挪出去，写成 `store4h(…, MM&, MM&, …)`，
   调用方因此把累加器放到栈上，1 KB 栈溢出，所有层都超时。改成先 `to_vector` 再按值传。
4. 程序内存：`se_pool` 末尾的 16 通道标量乘法 + 除法占 1.1 KB，换成向量 `mul` + `to_vector<uint8>(S)` 后是 0.65 KB。
   现在的分布：`core_0_2`（core 程序）4.4 KB（原 3.2），`convC16Chunk` 3.9 KB（原 3.1），SE 相关函数共约 1 KB。
5. （和 SE 无关的老坑）单层链如果用不满 4 个 core（例如单独跑 OC 并行 3 块的 Conv_92），会报 `Prod endpoint not set`：
   那个 core 的输入 fifo 整条链都没有 fill。和别的层串起来就没事。
