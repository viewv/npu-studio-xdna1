# ASR 40 层 Transformer NPU 实测与优化状态

> 更新时间：2026-11-17

## 1. 当前实测性能（T=140 / 7.0s 窗口，Ryzen 7840HS XDNA1）

| 执行后端 | 40 层纯 NPU 耗时 | 实时倍数 | 全链路端到端（含 FBank + Frontend + out_w） | 备注 |
|---|---:|---:|---:|---|
| **Python CPU 参考**（`reference.py`, `float32`） | `1,111.0 ms`（中位 `1,252.6 ms`） | ~6.3× | ~1,540 ms（优化前前/后处理） | 单纯对比用基线 |
| **Python CPU 纯 6 GEMM**（OpenBLAS `float32`） | `176.1 ms`（中位 `197.9 ms`） | ~39.7× | — | 不含 LN / Attn / GELU / 激活 |
| **4 核 NPU**（`npu/asr/encoder_npu.py`） | **`293.4 ms`**（中位 `294.0 ms`） | **23.9×** | **最快 `350.5 ms` / 中位 `492.6 ms`** | **100% 稳定**，支持 `from_cache`（冷启动 `6.8s`） |
| **4 核 NPU C++ 常驻版**（`npu/asr/asr_npu.cpp`） | **`286–289 ms`**（旧 `307–341`） | **~24×** | **`307–309 ms`**（旧 `342–363`；CPU 仅 `~22 ms`） | **脱离 Python**，冷启动 **`0.52–0.73s`**，支持 `stdin/stdout` 常驻；只有 7 秒档 |
| **16 核 NPU**（`npu/asr/encoder_16c.py`） | **`215.9 ms`**（中位 `217.6 ms`） | **32.4×** | **`256.2–260.8 ms`** | 多句连续切换偶发 MemTile/XRT 超时或漂移；11-17 负载 5–6 时复测 247–250 ms（新旧内核背靠背相同） |

> 11-17 下午的数字是在机器负载 4–6（桌面在用）时测的，绝对值偏高；同一时段的前后对比才可信。

### 按说话长度分档（4 核，40 层纯 NPU，`python -m npu.asr.encoder_npu --buckets`）

每行 W 个 token（4 行共 4W，每 token 50 ms），挑 `4W ≥ valid_t + 2` 的最小档。分档后有效 token 上的输出和 7 秒窗口的 NPU 输出**逐字节相同**（两段样本截成 1.5–5.9 s 共 10 段，全部一致，文字相同）。

| 档 | 窗口 | 改动前（7 秒窗固定） | 改动后 |
|---|---|---:|---:|
| W=10 | 2 s（40 token） | 290–330 ms | **132 ms** |
| W=15 | 3 s（60 token） | 290–330 ms | **146 ms** |
| W=25 | 5 s（100 token） | 290–330 ms | **204 ms** |
| W=35 | 7 s（140 token） | 328 ms（同时段） | **290 ms** |

（同一时段 A/B：权重不广播 + 标量 LN 时 W=10/15/35 = 189/206/332 ms；只加广播 141/179/328 ms；再加向量 LN 132/146/290 ms。）

### 已完成的优化
1. **Attention (`op=6`) 向量化**：`conv_c16.cc` 中 `attn_step` 改写为 `aie::mmul<4, 8, 8>` + `-DNO_K3`，4 核 40 层从早期基线 `~357 ms` 降至 **`293.4 ms`**（`max_diff == 0`）。
2. **前/后处理向量化（`FastFrontend` + `fbank_window`）**：
   - `fbank_window`（`sliding_window_view` + 批量 `rfft` + 预计算 Mel 矩阵）：`10.64 ms` → **`3.66 ms`**（`max_diff = 0.0`）。
   - 3 层卷积前端 + `lin_w`（`im2col` + `float32` BLAS GEMM）：`376.4 ms` → **`22.6–35.9 ms`**（独立基准 `min 29.5 ms`）。
   - `out_w` 预转置缩放 `float32` 投影：`52.4 ms` → **`3.8–4.7 ms`**。
3. **4 核权重磁盘缓存（`NPUTransformer40.from_cache`）**：缓存至 `~/.npu/asr/asr_4c_weights.npz`（原来在 `~/.npu/cache/`，会被 `npu.check` 和清 JIT 缓存一起删掉，已挪出），冷启动+预热从 `16.5s` 降至 **`6.8s`**，避免每次启动校准拉满 CPU。
4. **C++ XRT + OpenBLAS 独立常驻后端（`npu/asr/export_c_bundle.py` + `npu/asr/asr_npu.cpp`）**：
   - 导出模型包至 `~/.npu/asr/asr_4c_bundle`（`final.xclbin`、`insts.bin`、`weights.bin`、`vocab.txt`）。导出脚本在临时 JIT 缓存里现编 xclbin，不再写死缓存哈希（改了内核要重新导出）。
   - **必须链 OpenBLAS**（编译命令见 `asr_npu.cpp` 文件头）：系统 `-lcblas` 是 netlib 参考实现，前端会从 13 ms 变成 300 ms、`out_w` 从 4 ms 变成 230 ms。
   - 编译产物 `~/.npu/asr/asr_npu_cpp` 冷启动 **`0.48–0.63s`**，FBank (`~5.2 ms`) + 卷积前端 (`~13.1 ms`) + `out_w` (`~3.9 ms`) 合计仅 **`~22 ms`**，端到端 **`342.1–363.3 ms`**，支持无参数进入 `stdin/stdout` 守护模式。

5. **短窗口分档（`attn_step` 按行宽 W 计算）**：注意力内核里写死的 35 / 70 / 140 改成按本 core 的有效宽度 W 算循环次数（缓冲区仍按 W=35 的最大值排）。
   GEMM 和 LN 本来就跳过有效宽度外的像素组，主机侧描述符、TAP、`attn_ref` 也早就支持任意 W，所以不需要动 `CW` / `E_IN`。
   单层注意力 W=35 / 15 / 13 / 10：4.09 / 1.07 / 0.90 / 0.70 ms，全部逐字节一致（`attn15`、`attn13`、`lm15` 已进 `npu.check`）。
   档位要求 `4W ≥ valid_t + 2`：卷积前端里 token t 的感受野到第 5t+7 帧，窗口外是零而窗口内是静音帧，两者不同。
   W=20 的切分会选到 9216 B 的权重元素，核内内存分配失败（`Basic sequential allocation failed`），暂时不用这一档。
6. **权重广播（`Plan.w_bcast`）**：行并行的链（ASR 全部 360 个算子）里 4 个 core 每步的权重元素逐字节相同，原来每个 core 各从 DDR 读一份。
   改成一个 ObjectFifo 广播给 4 个 core、只读 core 0 那份，权重 DDR 流量 ÷4（主机侧权重布局不变，`C16Chain` 打包时核对 4 份相同）。
   `NPU_W_BCAST=0` 可关（改了要清 JIT 缓存）。短窗口收益最大：W=10 189 → 141 ms。
7. **LayerNorm 向量化**：`ln_step` 两遍都改成一次 16 通道，乘法用 64 位累加器、移位按向下取整，和 int64 整数参考逐位一致。
   单层 0.97 → 0.51 ms（含约 0.3 ms 固定调用开销）。程序内存只剩约 100 B：给 `rsqrt_q12`、`mean_rstd_q12`、`gather_rows_16` 加了 `minsize` 才放下。

## 2. 瓶颈分析与后续优化方向

1. **段间调用开销实测很小**：将 40 层从 8 段（每段 5 块）合并为 5 段 / 4 段（`nb=8 / 10`），40 层 NPU 估算仅从 `289.5 ms` 变为 `286.3 / 287.7 ms`（仅差 **2–3 ms**），瓶颈在 NPU 核内算子本身。
2. **NPU 核内算子瓶颈**：LN 已向量化、注意力已按窗口宽度算；7 秒档里 GEMM 约 108 ms，其余主要是注意力（每层约 4 ms）。
3. **短窗口的下限约 130 ms（W=10）**：和窗口长短无关的部分是**步数**——每个 7 秒窗 34,560 步，每步只算 16 个输出通道，
   却要重新搬一整个 7.5 KB 输入元素（IC 分块按 OC 份数重读输入）。下一步是每步算更多输出通道（受 64 KB 数据内存和 `ACC_CHUNKS` 限制），
   或者短窗口用更小的 `CW`（需要先去掉 `CW=40` 的写死处）。
4. **和 CPU 版（`asrd`，4 线程 3 秒语音约 60 ms）的差距**：CPU 版按实际长度算。NPU 有了分档以后 3 秒档 146 ms，仍是 CPU 的 2 倍多，
   但已经能跟上输入法每 300 ms 一次的边说边出：3 秒以内一次约 130–150 ms，5 秒以内约 200 ms，7 秒约 290 ms。
5. **工程化常驻方向**：
   - 已落地 **4 核 C++ XRT + OpenBLAS 常驻后端**（`npu/asr/asr_npu.cpp`），可直接作为子进程接入输入法后台。
   - **C++ 版还只有 7 秒档**：要分档需要导出每档的 xclbin + 权重（`export_c_bundle` 按 W 循环），并让前端按档位的帧数算（现在写死 `T_WIN=140`）。
