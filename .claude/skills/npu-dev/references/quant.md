# 量化方案（真实 RVM 编码器）

代码：`npu/rvm/encoder_ref.py`（抽图 + 浮点参考）、`npu/rvm/encoder_q.py`（整数模拟，`Cfg` 切换方案）、
`npu/rvm/encoder_npu.py`（冻结参数 → NPU）。

```bash
python -m npu.rvm.encoder_ref                  # 浮点参考 vs onnxruntime (应该到 1e-5)
python -m npu.rvm.encoder_q                    # 各方案的误差表 (约 1 分钟)
python -m npu.rvm.encoder_q "aq='channel',pct=0,rq='m16'"   # 指定方案
python -m npu.rvm.encoder_npu --iters 50       # NPU 真实权重: 和模拟逐字节比 + 对浮点的余弦 + 耗时
```

## 选定的方案

| 部分 | 做法 | 为什么 |
|---|---|---|
| 激活 | 对称 int8、零点 0、**逐通道比例**（`aq=channel`） | MobileNetV3 通道间范围差很多倍；逐张量 f4 余弦只有 0.65–0.84 |
| 范围 | 每个通道在校准集上找让量化 MSE 最小的截断（`pct=0`） | 比最大值 / 百分位都好一点 |
| 逐通道比例怎么落地 | 生产者：逐通道 M 本来就有，直接量化到各通道自己的比例；消费者：输入比例折进权重 `W[o,c]·s_x[c]` 再按输出通道量化 | 精确，不加内核代码 |
| 权重 | 对称 int8，逐输出通道 | dw 卷积按整层量化很差 |
| 重新量化 | `m16`：`sat16(acc >> s1)` × M[c]（int16）`>> s2`；s1 由校准集上的 |acc| 最大值 × 2 定 | 和浮点乘的结果几乎一样（f4 0.873 vs 0.881） |
| bias | int32，`round(b / s_w[o])`，累加器初值 | — |
| ReLU | int8 的 0..127 | 用 uint8 0..255 只多一点点（f1/f2 +0.001），不值得改内核 |
| hardswish | 先量化到 1/q_c（q_c 整数，3 和 6 是精确的 3q、6q），`yt = y·clamp(y+3q, 0, 6q)`，再 m16 一次到输出比例 | 内核 `post_act`，逐通道 q3/q6/M2 |
| HardSigmoid（SE） | FC2 量化到 6/256，输出 `y + 128`（uint8，比例 1/256） | 正好等于 clamp(x/6 + 0.5) |
| SE 的乘 | 折进投影层权重 `(W·s + 128) >> 8`（内核每步原地） | — |
| 残差 | 单位权重 `w_r[o] = round(s_r[o] / s_w[o])`；要求 `s_w ≥ s_r / 127` | 拼接视图 + 1×1 |
| 池化 | `(Σ·M + 2^21) >> 22`，比例不变 | — |
| 输入 | 主机把归一化后的图按通道量化成 int8（3 → 16 通道补零） | — |

## 误差（8 张评估图的平均余弦，对浮点 = onnxruntime）

| 方案 | f1 | f2 | f3 | f4 |
|---|---|---|---|---|
| 逐张量激活、最大值 | 0.980 | 0.839 | 0.775 | 0.653 |
| 逐张量激活、p99.9 | 0.990 | 0.934 | 0.917 | 0.837 |
| **逐通道激活、MSE 截断、m16（NPU 上跑的）** | **0.998** | **0.966** | **0.943** | **0.879** |
| 同上，16 位激活 + 16 位权重（诊断） | 1.000 | 1.000 | 0.999 | 0.998 |
| onnxruntime int8 静态量化（逐通道权重，最好的一种：Percentile + QUInt8） | 0.994 | 0.931 | 0.894 | 0.841 |

误差几乎全来自 8 位激活（只把权重换成 16 位几乎不变）。再往上要量化感知训练或部分层 16 位激活。
**还没看最终 alpha**：校准 / 评估图是系统壁纸（`encoder_ref.images()`，没有人像），要用真实摄像头画面校准并接上浮点解码器看 alpha 误差。

## 坑

- **死通道**（权重全 0）：按通道最大值算的比例 ≈ 0 → bias / 比例溢出（int64 里变 NaN，NPU 上整通道饱和）。比例设下限（通道最大值的 1e-3）。
  16 位诊断能把这类 bug 和"8 位噪声"分开：方法对的话 16 位应该接近 1.0。
- **死通道的 hardswish q** 会算出上万（范围极小）→ q6 超 int16，NPU 上整通道错（模拟用 int64 不出问题）。q 封顶 4096。
- 导出给 NPU 的投影层权重必须是**乘 SE 之前**的（内核自己折）；导出乘过的会乘两次。
- HardSigmoid 的输出是 uint8（0..255），读回来和模拟比较时按字节比，别按 int8。
- 定位 NPU 和模拟不一致：逐层读回张量比（`encoder_npu.read_tensor`），第一个不一致的层再用 numpy 拿几种假设去对 NPU 的输出。
