# 性能测量方法和已知数字（7840HS）

## 方法

1. **边际耗时（首选）**：链按前缀逐层加，`T(前 k 层) − T(前 k−1 层)` 就是第 k 层在链里的真实代价。

   ```python
   import npu.chain_c16 as c
   names = c.CHAINS["mnv3"]; prev = None
   for k in range(1, len(names) + 1):
       r = c.run_one(",".join(names[:k]), 50)
       print(names[k-1], r["max_diff"], r["best"], None if prev is None else r["best"] - prev)
       prev = r["best"]
   ```

   单层调用的耗时里 0.25–0.4 ms 是固定成本（XRT 派发、流水线启停），**不能用来判断一层贵不贵**。
   例：Conv_144 单层 0.62 ms，改 acc 大小只快 8%，以为不是输入搬运的问题；看边际才发现它在链里占 0.75 ms，确实是输入搬运。

2. **纯计算 vs 额外开销**：`python -m npu.chain_c16 --compute <链>`。内核每行重复调用 r = 1/2/3 次，
   T(r) 对 r 的斜率 = 整条链的纯计算时间；截距 − 0.25 ms（固定）再除以层数 ≈ 每层额外开销（DMA 重编程、层间屏障、流水线灌满/排空、等数据）。
   判据：每层额外 ≤ 0.1 ms。

3. **对照实验**：怀疑某个因素时，只改它一个（并清 JIT 缓存）。权重 fifo 深度 1→2、acc 加倍这类实验都做过，结论记在 tiling spike 里。

4. 每点 50–100 次，看中位和最快；机器负载（`uptime`）> 2 时中位不可信。主机 CPU 时间用 `resource.getrusage` 差值。

## 已知的性能债（按收益排序）

1. 12×20 的 IC 分块 1×1（Conv_104/131/144/163，共 ~1.2 ms）：acc 只够每份 1 个输出组 → 输入按 OC 份数重读 7–10 遍。
   办法：省内存放大 acc（3×3 128 通道也走 IC 分块，W_MAX 降到 9 KB）；1×1 的输入元素去掉左右 PAD；或者用 memtile 缓存。
2. 12×20 的 5×5 dilation 2 depthwise（Conv_122/135，+0.36/+0.46 ms）：每 core 3 行 × 14–20 步。办法：像 OC 并行那样做"通道并行"。
3. 通用 3×3 只有专用版 61% 的速度，而 3×3 占全网 73% 计算：给常见的 ICP 做编译期特化分支（注意程序内存）。
4. 宽 20 补成 40：已经跳过补宽列的计算和读取，但输出块和 DMA 还按 40 走。
5. 更根本：memtile（每列 512 KB）缓存整张低分辨率激活 / 整层权重，重读走片上。改动最大，等算子补齐、整网能跑之后再评估。
